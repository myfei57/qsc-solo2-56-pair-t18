# 分级运行配额（Hierarchical Running Quota）

线路原先只有"到站 / 发车"两个总上限，各站台苦乐不均。现改成分级额度：
**线路 → 站台 → 列车** 各有一份，站台或列车不够时沿层级**向上借**，下个周期
归还，还不上按策略**降级**。配额台账、到发编排、审计读的是**同一份账**。

## 1. 唯一事实来源：只追加哈希链账本

所有配额状态落在存储根目录的 `quota-ledger.jsonl`，一行就是一笔**事务**
（含一个或多个事件），没有第二种可变状态：

- **只追加、历史不可变**：修正只能靠追加补偿事件（如 `loan defaulted → closed`
  的人工补还），旧行永不修改。
- **哈希链**：每行带 `prev_hash`（上一行 SHA-256）与本行 `hash`，删改任意一行
  都会让后续校验失败。`quota verify` / `/api/quota/hierarchy` 可巡检。
- **崩溃安全**：追加走 `fsync`；若掉电留下最后一行半截 JSON，启动或下一次打开
  时自动隔离到 `quota-ledger.jsonl.quarantine`（不静默丢弃），从断点续账。
- **并发安全**：进程内可重入锁 + `fcntl` 跨进程排他文件锁；"读台账 → 校验 →
  追加"整段在锁内，多线程/多进程并发借还不会基于过期状态超卖。
- **部分失败回滚**：业务校验全部通过后才把整笔事务一次写入；校验失败一个事件
  都不落盘。
- **幂等**：每笔事务有 `txn_id`，命令带幂等键（到发用 `op_id`），超时重试安全。
- **恢复即重建**：内存台账是账本的纯函数投影（`fold`），重启/回放/审计走同一条
  折叠路径，结果必然一致。

## 2. 分级额度与记账口径

每一级对**到站（arrival）**与**发车（depart）**各有一份发放量 `granted`：

- **线路发放量 = 全线硬总车位**。无论一笔占用的钱最终出自哪一级，每条在站/发车
  占用都占线路一个物理车位；全线活动占用合计达到线路发放量后，任何站台都不能
  再放进车（跨站台合计）。
- **站台发放量是其中的切片**：各站台切片之和 ≤ 线路总量。它决定该站台"自有"
  能托底多少。
- **列车发放量**：每列车进站自带的额度，优先使用。

一条占用的**资金来源**按 `列车自有 → 站台 → 线路` 就近选取：

1. 列车自有够：记列车占用，无贷款；
2. 列车空、站台切片未手满：开一笔 `列车 → 站台` 贷款，占用记站台；
3. 站台切片也满、但线路总车位有空：站台中转，开两级链路贷款
   `线路 → 站台` 与 `站台 → 列车`（后者 `chain` 指向前者），占用溯源记线路。

占用（`held`）只跟随实际占用在 `permit_released` 时回收；贷款状态
（`open / due / closed / defaulted`）只表示债务，不重复增减占用，避免双计。

## 3. 归还：两种模式都支持，风险不同

贷款的归还模式在**借出时**固定（事后改策略不影响存量贷款）。

| 模式 | 行为 | 风险 |
|------|------|------|
| `auto`（默认） | 车走释放占用即自动 `closed`；周期时间窗结束仍在站的借款列车**自动降级**腾位、结清贷款 | 可能误伤仍在站的车，需用周期长度把误伤窗口管住 |
| `manual` | 释放后贷款挂 `due`，必须操作员 `confirm-return` 才归还；周期到不自动砍车，逾期列车停止受理新到发，钉子户由人工/容量驱动降级 | 人工拖延导致额度沉淀 |

## 4. 降级策略

结算窗口（auto）或容量不足需要腾位时，按当前策略挑选列车：

- `priority`（默认）：**低优先级先砍**，优先级相同按到站序号（FIFO）。保护重点车。
- `arrival`：完全按到站先后砍，公平但不区分重点。

降级会：释放该列车在站占用（触发贷款结清/挂账）、置 `degraded` 标记停止受理，
需 `restore` 后恢复。

## 5. 周期结算（时间窗）

`settle` 是**单笔原子事务**，顺序：刷新各级额度 → 窗口内归还 `due` 贷款（出资方
新额度装得下才还）→ auto 模式按策略降级跨周期未还的列车 / manual 模式把到期
贷款挂 `due` → 实在无法结清的标 `defaulted` 永久挂账（后续可人工 `repay` 补还）。

控制循环可配置每 N 个周期自动结算（`quota.settle_every_cycles`，0 = 仅手动触发）。

## 6. 运维入口

HTTP（见 `/api/quota/...`）或 CLI：

```
psdline quota status                 # 三级台账 + 账本校验
psdline quota settle [--idem KEY]    # 推进周期（自动归还/降级）
psdline quota confirm-return [ID…]   # manual 人工确认归还
psdline quota downgrade TRAIN        # 人工降级
psdline quota restore TRAIN          # 恢复降级列车
psdline quota repay LOAN_ID          # 补还历史挂账贷款
psdline quota policy --return-mode auto|manual --downgrade-policy priority|arrival
psdline quota verify                 # 校验哈希链
```

## 7. 兼容性

旧的线路级 `QuotaRegistry`（"到站/发车两总上限"）保留为兼容状态视图与旧单测，
但**不再参与准入决策**；准入统一由分级账本裁决，避免两套账不一致。
